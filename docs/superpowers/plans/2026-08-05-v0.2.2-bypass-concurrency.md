# V0.2.2 Transparent Bypass and Managed Queue Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Add transparent default bypass to the base vLLM plus bounded managed-request and vision concurrency with FIFO queuing, cancellation, queue progress, and health metrics.

**Architecture:** Local health and startup-probe routes remain inside the proxy. Requests that do not require document/image adaptation or proxy-owned web tools are forwarded byte-for-byte to `VLLM_BASE_URL`, preserving method, path, query, status, headers, and response streaming. Managed `/v1/messages` requests pass through an in-process FIFO admission controller; media and web-tool workflows use a managed slot, while each visual model request uses a separate vision semaphore.

**Tech Stack:** Node.js 22, built-in `http`, `fetch`, Web Streams, `node:test`, Poppler, ImageMagick, Docker Compose.

## Global Constraints

- Keep one official `node:22-bookworm-slim` container.
- Keep persistent Git source, `node_modules`, npm cache, and APT cache volumes.
- Keep `VLLM_BASE_URL`, `VLLM_BASE_API_KEY`, `VLLM_VISION_URL`, `VLLM_VISION_MODEL`, and `VLLM_VISION_API_KEY`.
- Do not add Redis, a distributed queue, tenant identity, or rate limiting.
- Bypass requests must not enter the managed queue or be reserialized.
- Managed queue must be bounded, FIFO, cancellable, and timeout-aware.
- Client disconnect must abort queue waits and active upstream work.
- Proxy-owned web tool calls may buffer; ordinary/native tool responses must remain transparent streams.
