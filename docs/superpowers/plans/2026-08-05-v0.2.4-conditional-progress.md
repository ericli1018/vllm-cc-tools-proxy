# V0.2.4 Conditional Progress Implementation Plan

**Goal:** Prevent fast managed requests from displaying a completion-only proxy progress block while preserving queue and long-running task progress.

## Root cause

`ProgressStream.closeProgress(finalMessage)` called `update(finalMessage, { force: true })`. This forced the first visible text block at request completion even when all earlier progress updates were suppressed by `PROGRESS_VISIBLE_AFTER_MS`.

## Implementation

- Add a failing unit test for closing a never-visible progress stream.
- Add an end-to-end test for a quick managed WebSearch-capable request whose model does not call the tool.
- Append the final transition message only when `ProgressStream.visible` is already true.
- Preserve queue updates using explicit `force: true`.
- Preserve hidden SSE keepalive and model content-block index zero when no progress block exists.
- Version, verify, package and checksum release `0.2.4`.
