# V0.2.19.1 WebFetch Parallel Budget Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make managed WebFetch friendly to slower local vLLM deployments by processing independent fetches concurrently with a global maximum of three Processor model calls, configurable Processor endpoint credentials/model, and non-destructive task budgeting.

**Architecture:** Keep the existing WebFetch pipeline and prompt-directed Processor. Execute independent managed tool calls concurrently while protecting Processor inference with one proxy-wide semaphore. Keep URL/API key/model overrides in `webFetchProcessor`, add bounded concurrency/timeout controls, reserve one final model round near the task deadline, and normalize WebSearch domain arguments before either proxy execution or Claude Code handoff.

**Tech Stack:** Node.js 22+, native `fetch`, `AbortSignal`, existing `Semaphore`, Anthropic Messages compatibility layer, Node test runner.

## Global Constraints

- Release version is `0.2.19.1`.
- WebFetch Processor concurrency defaults to `3` and is strictly bounded to `1..3`.
- WebFetch Processor URL, API key, and model remain independently configurable through `WEB_FETCH_PROCESSOR_URL`, `WEB_FETCH_PROCESSOR_API_KEY`, and `WEB_FETCH_PROCESSOR_MODEL`.
- WebFetch Processor timeout defaults to `300000` ms.
- Managed model round timeout defaults to `360000` ms.
- Managed task hard cap defaults to `1800000` ms.
- Native Web Search server-tool emulation remains outside this release.
- Existing protocol validation, recovery, no-progress detection, and tool-result quarantine behavior must remain intact.
