# V0.2.22 Claude Code Native Web Lifecycle Implementation Plan

**Goal:** Move ordinary WebSearch/WebFetch execution boundaries back to Claude Code while keeping Proxy-owned SearXNG, WebFetch Processor, and awesome-web-fetch fallback at the child/result boundaries proven by diagnostic traces.

**Architecture:** Main-agent ordinary WebSearch/WebFetch tool uses are handed back unchanged to Claude Code. Native `web_search_YYYYMMDD` child requests remain Proxy-managed and execute SearXNG. Claude Code WebFetch content-processing child requests are detected and routed directly to the configured WebFetch Processor. Redirect/failure WebFetch tool results are enriched for the Base-model view through awesome-web-fetch without rewriting Claude Code's transcript.

**Tech Stack:** Node.js 22, Anthropic Messages/SSE, vLLM Anthropic-compatible endpoint, SearXNG, awesome-web-fetch, OpenAI-compatible WebFetch Processor.

## Global Constraints
- Preserve Claude Code native `Web Search(...)` / `Fetch(...)` lifecycle.
- Do not cap overall research depth with `MAX_TOOL_ROUNDS`; the limit remains only for one Proxy-managed child request.
- Do not intercept MCP or third-party web-like tool names.
- Diagnostic file tracing remains available but disabled by default.
- TDD for every behavior change.

### Task 1: Main-agent web tool handoff
- Add failing tests proving ordinary WebSearch/WebFetch are returned unchanged without calling SearXNG/awesome-web-fetch.
- Preserve native child requests as managed.
- Implement a request-mode flag passed into `runManagedLoop`.

### Task 2: WebFetch lifecycle registry and processor-child detection
- Add a bounded per-Claude-Code-session registry keyed by tool_use_id.
- Detect the observed `Web page content:\n---` child request shape.
- Route detected child content directly to `WEB_FETCH_PROCESSOR_*` and emit an Anthropic response.

### Task 3: Redirect/failure fallback enrichment
- Detect returned WebFetch tool_result blocks that represent redirect/fetch failure.
- Resolve the original tool_use from the registry.
- Run awesome-web-fetch + Processor once and replace only the Base-model-view tool_result.
- Cache enrichment per tool_use_id to prevent duplicate fetches on history replay.

### Task 4: Regression, docs, release
- Update legacy tests expecting synthetic server-tool behavior for ordinary aliases.
- Keep native web search server-tool lifecycle tests.
- Update version, README, CHANGELOG, env comments, release notes.
- Run full tests, syntax check, verify.sh, package, extract ZIP, and rerun release verification.
