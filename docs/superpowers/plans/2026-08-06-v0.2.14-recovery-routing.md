# V0.2.14 Recovery Routing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Route malformed no-tool model responses to either a short final-channel recovery or a tool-preserving continuation recovery, then feed recovered tool calls back into the normal managed loop.

**Architecture:** Add deterministic recovery classification and request builders in `managed-final.js`. Refactor `managed-loop.js` so ordinary and recovered responses share one dispatch path. Preserve V0.2.13 file diagnostics and add route metadata.

**Tech Stack:** Node.js 22+, ES modules, built-in `node:test`.

## Global Constraints

- Final-channel recovery removes tools only for conservatively identified completed answers.
- Continuation recovery preserves all original tools and tool choice.
- A recovered managed WebSearch/WebFetch call must execute normally.
- A recovered non-managed tool call must return to Claude Code unchanged.
- One invalid response receives at most one recovery call.
- Main logs must not contain protocol snippet content.
