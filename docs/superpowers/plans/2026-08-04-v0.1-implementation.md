# VLLM-CC-TOOLS-PROXY V0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Deliver a tested, deployable V0.1 package that adapts Claude Code PDF/image content and managed web tools before local vLLM.

**Architecture:** A zero-runtime-dependency Node.js 22 ESM application exposes four service modes from one repository. Proxy orchestration uses built-in HTTP/fetch/streams; parser modes call bounded OS utilities installed by the official-Node bootstrap container.

**Tech Stack:** Node.js 22 ESM, built-in `node:http`, `fetch`, `node:test`, Poppler, ImageMagick, Tesseract, Docker Compose.

## Global Constraints

- Compose application services use the official `node:22-bookworm-slim` image.
- Startup scripts clone or fast-forward pull `https://github.com/ericli1018/vllm-cc-tools-proxy`.
- OCR, image parser, document parser and Vision URLs are independently configurable.
- Raw Base64 never reaches vLLM and never appears in normal logs.
- Managed tasks stream truthful progress and abort on client disconnect.
- No Redis, object storage, queue or shared host workspace in V0.1.
