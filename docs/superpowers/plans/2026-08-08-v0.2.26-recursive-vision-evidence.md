# V0.2.26 Recursive Vision Evidence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver V0.2.26 with media-before-preflight routing, selective/adaptive PDF vision, recursive original-source crops, and safe Vision diagnostics.

**Architecture:** Preserve the current adapters and managed loop contracts. Extend visual asset metadata so crop rendering can return to the root PDF/image source, then reorder the managed media path so adaptation completes before Base token preflight and scheduling classification.

**Tech Stack:** Node.js ESM, node:test, Poppler (`pdfinfo`, `pdftotext`, `pdfimages`, `pdftoppm`), ImageMagick, Ollama/OpenAI-compatible Vision APIs.

## Global Constraints
- Runtime release: `0.2.26`.
- npm package release: `0.2.26`.
- No new ENV variables.
- Base vLLM must not receive raw PDF/image blocks for media-managed requests, including `/v1/messages/count_tokens`.
- Vision provider remains selected only by existing `VLLM_VISION_*` settings.
- Keep WebSearch, WebFetch, managed scheduling and response-language behavior unchanged.
- Cache generations must change from V0.2.25.2.
