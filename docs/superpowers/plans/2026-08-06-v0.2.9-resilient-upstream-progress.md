# V0.2.9 Resilient Upstream and Immediate Progress Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make managed WebFetch failures recoverable, align the awesome-web-fetch contract, make Base vLLM timeouts configurable and diagnosable, and deliver every progress state transition to Claude Code immediately.

**Architecture:** Keep the existing managed-tool loop and Anthropic SSE envelope. Add a small WebFetch adapter for the deployed backend contract, return managed-tool failures as correlated `tool_result` errors instead of aborting the whole request, add a native Base upstream HTTP client with explicit header/body/connect timeout stages, and evolve `ProgressStream` into pending-snapshot plus state-revision delivery. No raw prompt, page content, API key, or full local path may be logged.

**Tech Stack:** Node.js 22 ESM, native `node:http`/`node:https`, Anthropic Messages/SSE compatibility, Node test runner.

## Global Constraints

- Release version: `0.2.9`.
- Preserve transparent bypass behavior for ordinary Anthropic requests.
- Preserve SSRF rejection for private WebFetch targets.
- `WEB_FETCH_URL` is treated as the exact configured endpoint; do not append `/v1/fetch`.
- `WEB_FETCH_API_KEY` is optional and must never appear in logs or tool results.
- Managed WebFetch service errors must become `tool_result` blocks with `is_error: true`; they must not terminate the entire Claude Code request.
- State changes emit an immediate real `content_block_delta`; 30-second Semantic Heartbeat only reports unchanged waiting state.
- Initial progress suppression must retain the latest pending state and reveal it after `PROGRESS_VISIBLE_AFTER_MS` when work is still active.
- Base upstream timeout defaults: connect `10000`, headers `900000`, body idle `900000` milliseconds.
- Error logs may include stage, elapsed time, safe host and cause code; never prompt or response content.
