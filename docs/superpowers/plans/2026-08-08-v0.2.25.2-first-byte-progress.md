# V0.2.25.2 First-Byte Progress Hotfix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Emit an immediate model-progress update when the first upstream Base-vLLM response bytes arrive, and expose enough timing/byte diagnostics to distinguish TTFT from active streaming.

**Architecture:** Keep the V0.2.25.1 Anthropic SSE transport and managed-loop contracts unchanged. Detect the first raw upstream chunk of each managed model round in the request-scoped byte callback, emit one forced progress update for that round, and add first-byte/progress diagnostics using the existing request-scoped counters and model timing state.

**Tech Stack:** Node.js 22+, Anthropic Messages SSE, existing `ProgressStream`, Node test runner.

## Global Constraints

- External runtime version: `0.2.25.2`; npm metadata: `0.2.25+hotfix.2`.
- No new environment variables.
- Do not change WebSearch fast-lane scheduling, large-context gating, WebFetch/Ollama routing, tool lifecycle, or timeout policy.
- At most one immediate first-byte progress update per model round; do not emit progress for every SSE chunk.
- Preserve the 30-second semantic heartbeat after first-byte notification.
