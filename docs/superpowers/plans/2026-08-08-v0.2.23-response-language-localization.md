# V0.2.23 Response Language & Status Localization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add locale-controlled model output and Proxy status localization with English fallback.

**Architecture:** Introduce one canonical locale registry and one Anthropic system-policy injector. Route all user-visible Proxy status generation through the registry while preserving technical literals. Apply the language policy to all Base-model `/v1/messages` and `/count_tokens` paths, and pass the Processor-specific instruction into WebFetch Processor calls.

**Tech Stack:** Node.js 22+, ES modules, `node:test`, existing Anthropic Messages proxy pipeline.

## Global Constraints
- Supported locales: `zh-TW`, `zh-CN`, `en-US`, `ja-JP`, `ko-KP`.
- Missing, blank, or invalid `MODEL_RESPONSE_LANGUAGE` falls back to `en-US`.
- Only one new ENV: `MODEL_RESPONSE_LANGUAGE`.
- Preserve technical literals verbatim.
- Keep prompt instructions short.
- No unrelated refactor.
