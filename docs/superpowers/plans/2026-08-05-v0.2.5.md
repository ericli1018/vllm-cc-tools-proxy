# VLLM-CC-TOOLS-PROXY V0.2.5 修改規劃

日期：2026-08-05  
基線：V0.2.4  
建議版本名稱：Historical Media Deduplication and Managed Keepalive

---

## 1. 本版要解決的實際問題

完整流程顯示：

```text
Read(PDF)
→ Proxy 執行一次 PDF / Visual 分析
→ 模型呼叫 Write
→ 下一個 /v1/messages 又重新執行同一份 PDF / Visual 分析
```

原因是 Claude Code 每一輪會重新送出完整 Messages History。

舊的 PDF Base64 仍存在先前的 `tool_result` 中。Proxy 掃描整段歷史時，再次將同一媒體判定為新的 Managed Work。

V0.2.5 必須保留：

```text
每輪都把歷史中的 PDF / Image 轉成 Base vLLM 可接受的文字
```

但改成：

```text
只有尚未分析過的媒體才呼叫 Visual vLLM
```

---

## 2. 不採用「只掃最新訊息」

不能單純改成：

```text
只處理最後一個 user message
```

原因：

1. 使用者後續可能繼續詢問先前 PDF。
2. Base vLLM 仍會看到歷史中的 raw document / image block。
3. vLLM Anthropic Endpoint 可能再次拒絕不支援的媒體 Content Block。
4. 後續問題仍需要先前文件的 Markdown / Visual Analysis。

正確做法是：

```text
每輪掃描所有相關 Content Blocks
→ 每個媒體計算 Fingerprint
→ 快取 Hit：直接替換成既有分析結果
→ 快取 Miss：執行一次分析並寫入快取
```

---

## 3. 新增三種路由決策

### `bypass`

```text
沒有 PDF / Image
沒有 Managed Web Tool
```

行為：

```text
Raw Request 透明轉送 VLLM_BASE_URL
```

### `cached_transform`

```text
Request 含 PDF / Image
但全部媒體均可從快取取得結果
```

行為：

```text
不進 Managed Queue
不呼叫 Visual vLLM
不建立可見 Progress Block
將 raw media block 替換成 cached normalized content
直接串流 Base vLLM
```

### `managed`

```text
至少一個媒體 Cache Miss
或需要 WebSearch / WebFetch / Managed Tool Loop
```

行為：

```text
進 Managed Queue
執行實際工作
必要時顯示可見進度
全生命週期保持不可見 SSE ping
```

---

## 4. Media Fingerprint

每個 PDF / Image 在 Base64 Decode 後計算：

```text
SHA-256(decoded bytes)
```

完整 Cache Key：

```text
media_sha256
+ media_type
+ parser_pipeline_version
+ visual_prompt_version
+ VLLM_VISION_MODEL
+ RESOURCE_PROFILE
```

範例：

```text
sha256:8f...
|application/pdf
|pipeline:v3
|visual-prompt:v2
|model:qwen3.6:27b-q4_K_M-cc
|profile:default
```

當以下任一條件改變時，自動 Cache Miss：

```text
文件解析流程版本
Visual Prompt
Vision Model
Resource Profile
```

避免沿用不相容的舊分析結果。

---

## 5. 快取內容

保存：

```text
Normalized Markdown / XML
頁數
原生文字提取結果
Visual Analysis
warnings
truncated 狀態
pipeline metadata
created_at
last_used_at
size
```

不保存：

```text
原始 Base64
Authorization Header
完整 Claude Code Request
完整使用者 Prompt
Vision API Key
Base API Key
```

PDF 原始檔與切圖只保留於 Request-scoped temp directory，完成後刪除。

## 6. Persistent Runtime Volume

新增獨立 Named Volume：

```yaml
volumes:
  proxy-source:
  proxy-npm-cache:
  proxy-apt-cache:
  proxy-data:
```

掛載：

```text
proxy-data:/var/lib/vllm-cc-tools-proxy
```

用途：

```text
media analysis cache
cache index
atomic cache temp files
```

不把 Runtime Cache 放入：

```text
Git working tree
node_modules
npm cache
```

這樣 Source 更新與 Runtime Data 不互相污染。

---

## 7. Cache 限制

不增加大量 ENV。

沿用：

```env
RESOURCE_PROFILE=default
```

內建策略建議：

### `small`

```text
Cache upper bound: 512 MiB
Retention target: 3 days
```

### `default`

```text
Cache upper bound: 2 GiB
Retention target: 7 days
```

### `large`

```text
Cache upper bound: 10 GiB
Retention target: 30 days
```

清理策略：

```text
LRU
+ TTL
+ 啟動時清理 incomplete temp files
+ 寫入使用 atomic rename
```

Cache 清理失敗不能阻止 Proxy 啟動，只記錄 warning。

---

## 8. Request 內去重

同一個 Request 可能重複包含相同文件。

流程：

```text
掃描 Content Blocks
→ 依 Cache Key 分組
→ 每個唯一 Key 只分析一次
→ 將同一結果替換到所有對應位置
```

例如：

```text
同一 PDF 出現 3 次
→ Visual vLLM 只呼叫 1 次
```

---

## 9. 跨 Request Singleflight

兩個並行 Request 可能同時送入相同 PDF。

新增：

```text
MediaAnalysisRegistry
```

Key：

```text
Cache Key
```

行為：

```text
Request A：Cache Miss，建立 Analysis Job
Request B：同 Key，加入既有 Job
→ 不建立第二個 Visual Job
```

完成後：

```text
A、B 共用同一分析結果
```

取消規則：

```text
單一等待者取消
→ 只移除該等待者

所有等待者都取消
→ Abort 共用 Analysis Job
```

避免相同大型 PDF 同時壓入 Visual vLLM。

---

## 10. Progress 顯示規則

### `bypass`

```text
完全不建立 Proxy Progress
```

### `cached_transform`

```text
完全不建立可見 Progress
不顯示「處理完成」
```

因為沒有執行實際昂貴工作。

### `managed`

可見 Progress 僅在以下條件成立時建立：

```text
進入 Queue
或
工作時間超過延遲門檻
或
發生可觀察的階段轉換
```

例如：

```text
正在解析 PDF…
正在使用視覺模型分析第 1/2 批頁面…
視覺模型要求檢視 1 個局部區域…
文件內容已就緒；正在交給主模型…
```

完成訊息只在 Progress Block 已存在時追加：

```text
處理完成；正在回傳模型結果…
```

## 11. Managed Keepalive 修正

V0.2.5 將不可見 Anthropic SSE `ping` 維持到整個 Managed Response 結束。

生命週期：

```text
Managed SSE Headers
→ Queue
→ Parser
→ Visual vLLM
→ Crop Loop
→ Base vLLM TTFT
→ Base vLLM SSE
→ message_stop / connection close
→ 停止 ping timer
```

預設：

```text
每 5 秒 event: ping
```

不靠固定顯示：

```text
…
仍在處理…
```

避免污染 Claude Code 畫面。

---

## 12. SSE 安全 Multiplexer

不能在任意 byte 中間插入 ping。

新增：

```text
SSE Frame Multiplexer
```

行為：

```text
只在完整 SSE frame 邊界插入 event: ping
不切斷 data: JSON
不重排 upstream event
不 Buffer 完整 Response
只暫存未完成的最後一個 frame
```

適用：

```text
Managed Request 最後的 Base vLLM 串流
```

不適用：

```text
純 Bypass
```

Bypass 仍維持原始 byte stream，不注入 Proxy ping。

---

## 13. Media Transformation

每輪送往 Base vLLM 前：

```text
raw PDF / image block
→ cached 或 freshly generated normalized text block
```

範例：

```xml
<document
  source_sha256="..."
  media_type="application/pdf"
  pages="4"
  parser_pipeline="v3"
  visual_model="qwen3.6:27b-q4_K_M-cc">

<page index="1">
...
</page>

</document>
```

不得送往 Base vLLM：

```text
原始 Base64
本機 temp path
Cache filesystem path
Vision API response raw payload
```

---

## 14. Cache Hit 不得進 Managed Queue

Queue 僅控制昂貴工作：

```text
Parser Cache Miss
Visual Analysis
WebSearch
WebFetch
Managed Tool Loop
```

Cache Hit Transformation：

```text
不占用 Managed Slot
不占用 Vision Slot
```

這樣後續對同一 PDF 的提問不會被新的大型文件工作阻塞。

## 17. `</thinking>` 的處理邊界

V0.2.5 不修改：

```text
<think>
</think>
<thinking>
</thinking>
```

理由：

```text
這是 Chat Template / Reasoning Parser / Model Protocol 問題
```

Proxy 不應粗暴刪除模型可見文字中的 XML-like Tag，否則可能：

```text
破壞程式碼
破壞文件內容
隱藏 Template 錯誤
誤刪使用者要求輸出的 Tag
```

V0.2.5 最多新增診斷 Log：

```text
reasoning_tag_visible_in_final_content
```

但預設不修改 Response。

## 18. 必要回歸測試

### 完整流程重現

```text
Request 1:
Read(PDF)
→ Visual 呼叫 1 次
→ Cache 寫入
→ Base vLLM 收到 normalized document

Request 2:
Write Tool Result + 完整歷史中的相同 PDF
→ Visual 呼叫仍為總計 1 次
→ 不顯示第二次 PDF 進度
→ Base vLLM 仍收到 normalized document
```

### 後續詢問

```text
使用者再次詢問同一 PDF
→ Cache Hit
→ 文件內容仍送入 Base vLLM
→ 不重新分析
```

### 同一 Request 重複媒體

```text
相同 PDF 出現兩次
→ 只分析一次
```

### 並行相同媒體

```text
兩個 Request 同時上傳相同 PDF
→ 只有一個 Visual Job
```

### Cache Invalidation

```text
Vision Model 改變
→ Cache Miss

Visual Prompt Version 改變
→ Cache Miss

Pipeline Version 改變
→ Cache Miss
```

### 持久化

```text
Proxy restart
→ 舊 Cache 仍可使用
```

### Progress

```text
Cache Hit
→ 零可見 Progress

快速 Cache Miss
→ 未超過門檻時零可見 Progress

長時間 Cache Miss
→ 顯示有效階段
```

### Keepalive

```text
Visual vLLM 長時間無輸出
→ 每 5 秒 ping

Base vLLM TTFT 長
→ 每 5 秒 ping

Base vLLM Token Stream 中斷 20 秒
→ ping 仍持續

message_stop
→ ping 停止
```

### 安全

```text
Raw Base64 不進 Base vLLM
Cache 不保存 Base64
Client cancel 清理 temp files
Incomplete cache file 不可被讀取
```
