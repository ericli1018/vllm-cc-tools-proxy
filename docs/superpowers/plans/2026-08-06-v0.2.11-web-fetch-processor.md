# V0.2.11 WebFetch Processor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add prompt-directed WebFetch processing, readable tool evidence, five simple configuration variables, guarded fallback, and release V0.2.11.

**Architecture:** Fetch and normalize the page first, clean it deterministically, then call an isolated OpenAI chat-completions Processor with no tools or Claude Code history. Render the processed result as a multiline VCC evidence block and add one short idempotent System supplement before the next Base-model round.

**Tech Stack:** Node.js 22 ESM, native HTTP/fetch APIs, Node test runner, Anthropic Messages requests, OpenAI-compatible chat completions.

## Global Constraints

- No new npm dependency.
- Expose exactly five `WEB_FETCH_PROCESSOR_*` variables.
- Processor failure must fall back to bounded cleaned evidence, not raw full-page forwarding.
- Successful managed tool results must not be JSON-stringified objects.
- Preserve transparent bypass behavior.
