# V0.2.24 Upstream Byte Progress Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show cumulative Base vLLM response bytes in the visible progress header and every 30-second semantic heartbeat.

**Architecture:** Count raw response-body bytes at the Base vLLM HTTP boundary before JSON/SSE decoding. Keep one request-scoped cumulative counter and pass a getter into `ProgressStream`, so multiple model rounds add to the same total. Render byte units centrally as B/KB/MB/GB and localize only the surrounding status text.

**Tech Stack:** Node.js 22+, native HTTP streams, Anthropic Messages/SSE compatibility layer.

## Global Constraints

- Runtime version: `0.2.24`.
- Count only response bytes received from Base vLLM; do not count Proxy-to-Claude-Code SSE bytes, request bytes, WebFetch Processor bytes, or SearXNG bytes.
- Accumulate across all Base model rounds in one managed Claude Code request.
- Use binary units (1024) and display `B`, `KB`, `MB`, `GB`.
- Keep all WebSearch/WebFetch lifecycle behavior from v0.2.23.2 unchanged.
- Keep MODEL_RESPONSE_LANGUAGE behavior unchanged except localized progress byte wording.
