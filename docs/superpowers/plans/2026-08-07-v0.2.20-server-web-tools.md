# V0.2.20 Unified Server Web Tool Bridge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert all explicit proxy-owned WebSearch/WebFetch aliases and dated native web tool names into an Anthropic-compatible server-tool lifecycle without losing mixed client-tool intent.

**Architecture:** Add one canonical web-tool matcher used by request definitions and model-emitted tool calls. Pure proxy-owned web calls execute inside the managed loop while emitting/collecting `server_tool_use` and matching result blocks. Mixed server/client calls return the pending `server_tool_use` plus client `tool_use` unchanged in intent; on the follow-up request, unresolved server calls are detected from history, executed, injected internally as correlated tool results, and surfaced as the first blocks of the continuation response.

**Tech Stack:** Node.js ESM, Anthropic Messages/SSE compatibility, existing SearXNG and awesome-web-fetch adapters, node:test.

## Global Constraints

- Public release version: `v0.2.20`.
- npm package version must remain valid SemVer.
- Capture only explicit aliases: `WebSearch`, `web_search`, `web_search_YYYYMMDD`, `WebFetch`, `web_fetch`, `web_fetch_YYYYMMDD` and matching native `tool.type`; never capture MCP/custom names containing those substrings.
- Preserve existing WebFetch Processor provider/concurrency behavior from v0.2.19.3.
- Preserve client tool calls and Anthropic mixed server/client semantics.
- No additional required ENV variables.
