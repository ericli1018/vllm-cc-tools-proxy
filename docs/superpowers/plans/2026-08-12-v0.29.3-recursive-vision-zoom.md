# V0.29.3 Recursive Vision Zoom & Overlapping Tiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a bounded `NEEDS_ZOOM` visual state so dense PDF pages can request region enlargement or fall back to overlapping tiles without treating density as a failed Vision response.

**Architecture:** Extend the existing Vision Output Contract and reuse the existing `request_image_crop`, `VisualAssetRegistry`, PDF region renderer, and `buildPdfTiles()` components. Explicit normalized ROI requests are executed as bounded crops; PDF DIAGRAM/DENSE_PAGE responses that declare `NEEDS_ZOOM` without usable ROI trigger deterministic overlapping page tiles, while SCHEMATIC retains whole-page + deterministic tiles with overlap raised to 20%. Whole-page and region evidence are merged with source provenance.

**Tech Stack:** Node.js ESM, existing Vision client, ImageMagick/PDF render pipeline, node:test.

## Global Constraints

- Baseline is v0.29.2 and release version is exactly `0.29.3`.
- Preserve v0.29.2 Vision timeout, THINK preservation, unavailable-evidence isolation, Document Map, progressive `Read.pages`, statusLine, Language Repair, and independent Base scheduling.
- Normalized ROI coordinates are integers in `[0,1000]`.
- Explicit ROI crop adds 12% outer margin before rendering.
- PDF DIAGRAM/DENSE_PAGE fallback tiles use 15% overlap; SCHEMATIC uses 20% overlap.
- Maximum zoom depth is 2; maximum ROI requests per response is 4; maximum automatic tiles per page is 12.
- `NEEDS_ZOOM` is an actionable valid state, not WEAK/FAIL and not cacheable until final evidence is produced.
- No new required ENV variables.
