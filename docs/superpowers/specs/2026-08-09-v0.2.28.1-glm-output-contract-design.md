# V0.2.28.1 GLM Output Contract Design

## Goal

Harden external GLM processors so final-language repair cannot silently return the wrong language, and Vision reasoning/control material cannot leak into engineering evidence.

## Scope

V0.2.28.1 changes only three contracts:

1. Final-language repair must pass a post-rewrite language classification before it is accepted.
2. GLM non-thinking requests must use provider-appropriate controls without assuming Ollama OpenAI compatibility and native Ollama share one mechanism.
3. Vision responses must remove reasoning-only material before normalized evidence is produced.

No PDF/Image routing, cache generation, Managed Loop policy, Read.pages behavior, ENV surface, or Vision crop geometry changes.

## Final Language Repair

After a repair backend returns structurally valid segments, concatenate the repaired prose and call the existing `classifyFinalLanguage(text, locale)`.

Acceptance:
- `decision=repair`: reject this backend with `language_not_compliant` and continue fallback routing.
- `decision=compliant` or `uncertain`: accept the rewrite; `uncertain` is retained for short/mostly-code outputs where the classifier lacks enough natural-language signal to prove non-compliance.

External failure falls back to Base repair. Base repair is subject to the same post-validation. If all repair backends fail, preserve the existing original-response fallback behavior.

Diagnostics must include detected language and classification decision when a backend is rejected for language non-compliance.

## GLM Non-Thinking Normalization

Provider behavior:

- Native Ollama `/api/chat`: continue `think=false`; prepend `/nothink` to the system instruction for GLM processor/vision requests when thinking is disabled, because the target GLM chat template recognizes `/nothink`.
- OpenAI-compatible vLLM: use `chat_template_kwargs.enable_thinking=false` and `preserve_thinking=false`.
- Ollama OpenAI-compatible `/v1/chat/completions`: keep `reasoning_effort=none` for compatibility, and also prepend `/nothink` to GLM processor system content when thinking is disabled. Do not send vLLM-only `chat_template_kwargs` to Ollama OpenAI compatibility mode.

No new ENV is introduced.

## Vision Reasoning Sanitization

Normalize a Vision model message into visible evidence before returning it:

1. Discard native `message.thinking` from evidence.
2. Strip complete `<think>...</think>` regions from `message.content`, case-insensitively.
3. Strip orphan `<think>` / `</think>` tags while preserving surrounding visible content.
4. Keep diagnostic detection of control tags on the raw response.
5. Add diagnostic `visual_reasoning_stripped` when native thinking or inline think regions/tags were removed.
6. Use sanitized visible content for assistant continuation messages and final `markdown` evidence.

Do not attempt generic XML removal; only the reasoning form that is proven by current GLM output is stripped in this hotfix.

## Cache Contract

Because cached Vision evidence produced by V0.2.28 may contain escaped reasoning content, the evidence semantics change. Bump:

- `visual-v6` → `visual-v7`
- `evidence-v2` → `evidence-v3`

Keep `media-v7` unchanged.

This intentionally invalidates old visual/evidence cache entries while preserving media identity rules.

## Verification

Required regression cases:

- External translation returns English with valid markers → rejected → Base repair used.
- Base repair still wrong language → rejected → original response returned.
- Valid zh-TW external translation → accepted.
- Native Ollama Vision with `think=false` carries `think=false` and `/nothink`.
- Ollama OpenAI language processor uses `reasoning_effort=none` plus `/nothink` and omits `chat_template_kwargs`.
- vLLM processor uses `chat_template_kwargs.enable_thinking=false`.
- Vision `message.thinking` is never included in evidence.
- Vision `<think>...</think>` content is removed while visible Markdown is preserved.
- Full test suite, syntax check, verify script, manifest, ZIP integrity, SHA256, and no `(1)` paths all pass.
