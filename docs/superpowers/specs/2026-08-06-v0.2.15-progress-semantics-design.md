# V0.2.15 Proxy-Turn Progress Semantics Design

## Goal

Make progress messages describe the proxy's current API turn instead of claiming the complete Claude Code task has finished.

## Scope

- Change visible progress copy and structured progress phases only.
- Preserve V0.2.14 Managed Tool Routing, Recovery Routing, WebFetch Processor, protocol diagnostics, and limits.
- Do not add environment variables.

## Response classification

When a buffered Anthropic response is ready:

1. Any `tool_use` block means the proxy turn is handing an action back to Claude Code. The closing progress message names the single tool when possible and uses phase `handoff_to_claude_code`.
2. No tool call plus non-empty visible `text` means the model completed this turn's answer. Use phase `returning_visible_response`.
3. Other valid output means only that model output is being returned. Use phase `returning_model_output`; never claim the whole task is complete.

Every classification reports `terminal_for_proxy=true` and `terminal_for_claude_task=false`.

## Streaming response semantics

For direct upstream SSE, close the progress block when the first model block arrives, using its block type:

- `tool_use`: the model started returning the next tool action.
- `text`: the model started returning this turn's visible answer.
- `thinking`: the model started returning thinking content.
- unknown/no block: the model started returning this turn's output.

## Heartbeats

Generic heartbeats say `主模型仍在處理本輪請求` rather than `目前任務仍在處理中`. Media heartbeats retain the file context while using the same proxy-turn wording.

## Error handling

Progress classification is pure and must not alter response blocks, stop reasons, tool calls, recovery decisions, or SSE payload ordering. Unknown response shapes use the conservative `returning_model_output` fallback.

## Verification

- Unit tests cover text, one tool, multiple tools, thinking-only fallback, structured close phase, generic heartbeat, media heartbeat, and upstream SSE first-block wording.
- Full existing suite and syntax checks must remain green.
- Release version, health endpoint, documentation, manifest, ZIP integrity, and clean extraction must report V0.2.15.
