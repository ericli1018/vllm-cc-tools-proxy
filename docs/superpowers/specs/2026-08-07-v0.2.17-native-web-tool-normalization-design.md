# V0.2.17 Native Web Tool Normalization Design

## Goal

Accept Anthropic native `web_search_*` and `web_fetch_*` server-tool definitions from Claude Code while continuing to use the proxy-owned SearXNG and WebFetch backends.

## Architecture

A new normalization module detects native web-tool definitions by `type` prefix, extracts local execution policy, and replaces each native definition with a standard Anthropic custom-tool definition containing `input_schema`. The normalized request is the only request sent to both `/v1/messages/count_tokens` and `/v1/messages`; policy metadata remains local and is never forwarded to vLLM.

## Policy enforcement

- `max_uses`: counted per canonical managed tool and per incoming request; failed attempts count.
- `allowed_domains` / `blocked_domains`: enforced on WebSearch results and WebFetch targets.
- `max_content_tokens`: conservatively converted to an output-character ceiling for WebFetch.
- `citations`, `user_location`, dynamic-filtering fields and unknown native fields: retained only as unsupported metadata for diagnostics; the proxy does not claim native Anthropic citation or dynamic-filtering parity.
- Both allowed and blocked domain lists in one tool definition are rejected as an invalid request.

## Compatibility

- Existing custom `WebSearch`, `web_search`, `WebFetch`, and `web_fetch` definitions are unchanged.
- Non-web tools are unchanged.
- Prefix matching supports current and future dated versions rather than hard-coding one version.
- Managed Loop, Recovery Routing, Usage Preservation and Progress Semantics remain unchanged except for receiving normalized tools and local policy.

## Error behavior

Normalization failures return a deterministic non-retryable 400 error. Policy-limit and domain-policy failures become managed tool results, allowing the model to choose another valid action without terminating the Claude Code task.
