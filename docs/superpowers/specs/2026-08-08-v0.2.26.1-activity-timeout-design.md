# V0.2.26.1 Activity-Aware Managed Timeout Design

## Goal

Prevent healthy streaming Base-model rounds from being terminated solely because wall-clock round time reaches 360 seconds.

## Contract

- `MANAGED_MODEL_ROUND_TIMEOUT_MS` is the first-response-byte deadline when upstream activity telemetry is available.
- Before the current round receives any upstream response byte, exceeding that deadline raises `managed_model_timeout`.
- After the first response byte arrives, the first-byte deadline is disarmed.
- Streaming after first byte is protected by the existing inactivity detector; 90 seconds with no new upstream response bytes raises `managed_model_stall_timeout`.
- Every new upstream response chunk refreshes activity through `lastByteAt`.
- `MANAGED_TASK_TIMEOUT_MS` defaults to disabled. Unset, empty, or `0` means no whole-task absolute deadline.
- An explicitly configured positive `MANAGED_TASK_TIMEOUT_MS` remains supported as an opt-in absolute task deadline.
- If upstream activity telemetry is unavailable, `MANAGED_MODEL_ROUND_TIMEOUT_MS` remains a bounded round timeout because first-byte state cannot be observed safely.
- Existing tool-specific timeouts, model token/context limits, loop protections, client cancellation, and disconnect handling remain unchanged.

## Configuration

- Keep `MANAGED_MODEL_ROUND_TIMEOUT_MS=360000` as the first-byte timeout default.
- Remove the forced 1800000 ms default for `MANAGED_TASK_TIMEOUT_MS` from deployment defaults.
- Keep optional pass-through support for `MANAGED_TASK_TIMEOUT_MS`.
- No new ENV variables.

## Observability

- Existing `managed_model_first_byte_received` remains the authoritative first-byte event.
- Heartbeat diagnostics continue reporting cumulative upstream bytes and model elapsed time.
- Timeout codes remain distinct: `managed_model_timeout`, `managed_model_stall_timeout`, and optional `managed_task_timeout`.
