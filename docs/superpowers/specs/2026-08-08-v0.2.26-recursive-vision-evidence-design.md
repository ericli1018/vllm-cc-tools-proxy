# V0.2.26 Recursive Vision Evidence Pipeline Design

## Goal
Keep all raw PDF/image interpretation inside the configured Vision provider while improving document fidelity and preventing raw media from reaching Base vLLM token preflight or inference.

## Architecture
1. Prepare request-scoped media handles and cache lookups.
2. Adapt uncached PDF/image media into text evidence before any Base `/v1/messages/count_tokens` call.
3. For PDF pages, extract native text first and select only pages that need visual analysis (low native text or embedded raster images).
4. Render selected PDF overview pages at an adaptive DPI targeting about 3500 px on the long edge, bounded to 220–320 DPI and final 4096 px safety normalization.
5. Vision analysis runs against the configured `VLLM_VISION_PROVIDER` only. It may request multiple crops over up to three rounds.
6. Every successful crop becomes a registered visual asset with root/parent lineage. A crop of a crop remains authorized.
7. PDF crops are re-rendered from the original PDF region at higher effective resolution (target ~2400 px long edge; max 600 DPI at depth 1, 720 DPI at deeper levels). Ordinary image crops always use the original image pixels, not a previously downscaled overview.
8. Final Markdown evidence replaces all raw media before Base token counting, large-context classification, and Base model inference.

## Visual asset contract
Each asset records `sourceId`, `rootSourceId`, `parentSourceId`, `depth`, `rootBox`, presentation dimensions, label, and source-kind metadata. Root image assets retain original bytes/dimensions. Root PDF-page assets retain the request-local PDF path, page number, page geometry, and overview DPI. Root crop budget is 8, nested depth is 3, and crop rounds are 3.

## PDF selection
A page requires visual analysis when native text is below the existing minimum threshold or when `pdfimages -list` reports embedded raster images for the page. Failure to inventory embedded images degrades safely to native-text selection and emits a warning rather than failing the document.

## Vision diagnostics
Every Vision call emits safe `vision_upstream_request` and `vision_upstream_response` events containing provider, backend host/path, model, image count, dimensions, elapsed time and status. No API key, image bytes or extracted page text are logged.

## Error handling
Crop validation remains recoverable inside the Vision loop. Raw media never falls back to Base Laguna. If the Vision worker cannot resolve a region within the crop limits, it must state uncertainty. A Vision service rejection remains a media-processing error rather than silently routing raw images to Base vLLM.

## Cache/versioning
Bump the media pipeline and visual prompt generations so 180-DPI/all-page legacy evidence cannot be reused by V0.2.26.

## Non-goals
No new ENV variables. Do not alter WebSearch, WebFetch, managed scheduling, response-language policy, or Base model timeout policy.
